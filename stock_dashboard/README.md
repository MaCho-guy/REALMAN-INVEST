# 주식 대시보드

jusikbot.com 의 **정보 구조**(야간 대체시세 → 시장 지표)를 따라 만든 Streamlit
대시보드입니다. 여기에 미국 종목 워치리스트와 밸류에이션 지표 섹션을 더했습니다.
UI·코드는 전부 새로 작성한 것이며 원 사이트의 복제가 아닙니다.

> 정보 제공 목적이며 투자 판단의 근거가 아닙니다. 시세는 지연될 수 있고
> 사용하는 데이터 소스는 어느 것도 공식 API 가 아닙니다.

---

## 1. 실행

### zip 파일이 무엇인가

보내드리는 `stock_dashboard.zip` 은 **대시보드 소스 코드 전체**입니다.
매번 전체가 새로 들어 있으니 **최신 것 하나만** 쓰시면 되고, 이전 것은
지우셔도 됩니다.

| | 용도 |
|---|---|
| 프리뷰 아티팩트 (링크) | 모양만 보는 정적 HTML. 설치 없이 바로 열림 |
| **zip 파일** | 실제로 돌리는 소스. 압축 풀고 아래 두 줄 |

```bash
pip install -r requirements.txt
streamlit run app.py
```

실데이터를 아직 연결하지 않으셨다면 **프리뷰만 봐도 충분합니다** —
레이아웃·탭 전환·나이트 모드가 그대로 동작합니다.


```bash
cd stock_dashboard
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

브라우저가 자동으로 `http://localhost:8501` 을 엽니다.

### 설치 없이 레이아웃만 먼저 보기

```bash
python -m tools.preview          # preview.html 생성 (다크)
python -m tools.preview --light  # preview-light.html
```

생성된 HTML 파일을 브라우저로 열면 됩니다. 숫자는 가짜(데모)입니다.

## 2. 화면 구성 — 요약 + 목적 기준 5개

기능이 아니라 **"무엇을 하려는 화면인가"** 로 묶었습니다. 전에는 탭이 13개였는데,
기능을 쌓은 결과였고 보유 종목 하나를 보려면 세 탭을 다 열어야 했습니다.

| 탭 | 목적 | 담긴 것 | 소스 |
|---|---|---|---|
| **0. 요약** | **휴대폰에서 10초** | 네 줄 — 내 종목에 생긴 일 · 시장 분위기 · 메모리 사이클 · 발굴은 어디서 | 아래 탭들의 캐시 재사용 |
| **1. 내 종목** | 가진 것에 대해 알아야 할 전부 | 지금 확인할 것(신규 공시·실적 임박·급변) → 시세 카드 → 공시 분석 3종 | 야후 · 네이버 · EDGAR · DART |
| **2. 종목 발굴** | 읽을 목록 줄이기 | 52주 위치 × 버핏식 품질 교차 (미국·국내) | 야후 · EDGAR companyfacts · DART |
| **3. 매크로** | 금리·물가·고용·반도체 사이클 | 시장가격(실시간) + **공포탐욕지수** + **VIX 기간구조** + 경제지표 13종, **임계값 도달 시에만** 신호+기사 | 야후 · CNN · FRED |
| **4. 밸류에이션** | 걸러낸 종목 판단 | 역DCF(요구 성장률 vs 과거 실제) + 사분면 + 야후 집계 지표 | EDGAR · DART · 야후 |
| **5. 메모리 사이클** | 사이클 국면 판정 | DIO 재고 지표(레이어 2) · 반도체 생산·PPI(레이어 1·4 대리) | DART · EDGAR XBRL · FRED |

**진단은 사이드바**에 있습니다. 데이터가 맞는지 확인하는 *도구*이고 매일 보는
화면이 아니라, 탭 5개는 목적만으로 채웠습니다.

### 요약 탭은 축이 다릅니다

5개는 **"무엇을 하려는 화면인가"**, 요약은 **"휴대폰에서 10초"** 입니다.
간간히 확인하는 용도라면 탭 5개를 돌 게 아니라 한 화면에서 끝나야 합니다.

```
지금 확인할 것이 없습니다.
네 가지를 다 봤고 올라온 것이 없습니다

[조용함]    내 종목        9종목 모두 조용함
[조용함]    시장 분위기     공포탐욕 63 (탐욕) · VIX 16.4 · 5년 중 20%
[볼 것 있음] 메모리 사이클   SK하이닉스 DIO +16일 · 반도체 산업생산 +7.7%
[조용함]    종목 발굴       책상에서 볼 것
```

**맨 윗줄만 보고 앱을 닫을 수 있어야** 합니다. 긴급한 게 있으면 그 카드만
요약에서 바로 펼쳐 보여줍니다 — 탭을 옮길 필요가 없습니다.

**발굴·밸류에이션은 일부러 뺐습니다.** 68종목의 10년 재무를 받아오는 작업이라
휴대폰 글랜스에 맞지 않습니다. 어디로 가면 되는지만 적습니다.

변화 감지는 요약 탭과 내 종목 탭이 **같은 함수**(`_detect_signals`)를 씁니다 —
두 화면이 다른 결과를 보여주면 신뢰를 잃기 때문입니다.

### 휴대폰에서 쓰기

사이드바에 **휴대폰 모드** 토글이 있습니다. 켜면 무거운 것을 **DOM 에 아예 넣지
않습니다**:

| 켜면 생략 | 왜 |
|---|---|
| 공시 분석 본문 | 종목당 50KB 넘고 휴대폰에서 읽을 분량이 아닙니다 |
| 야후 집계 지표표 | 9컬럼 — 390px 화면에서 못 읽습니다 |

요약·시세·매크로·사이클은 그대로입니다. 탭별 분량(데모 기준):

| 탭 | 크기 |
|---|---|
| 요약 | 2KB |
| 종목 발굴 | 6KB |
| 매크로 | 28KB |
| 밸류에이션 | 33KB |
| 내 종목 | 75KB → 휴대폰 모드로 크게 줄어듭니다 |

### 반응형 CSS — 없던 걸 넣었습니다

`.dash-grid` 규칙이 **`tools/preview.py` 에만 있고 `theme.py` 에는 없었습니다.**
프리뷰는 정상인데 **실제 앱에서는 카드가 그리드로 배치되지 않았습니다** —
프리뷰만 확인한 탓에 놓친 버그입니다. 넣으면서 휴대폰 규칙도 함께 넣었습니다:

| 화면 폭 | 처리 |
|---|---|
| 1100px 이하 | 카드 2열 |
| 640px 이하 | 카드 2열 · 표 가로 스크롤 · 큰 숫자 축소 |
| 640px 이하 (SVG) | 차트 글자 9px → 13px |

**SVG 글자 크기가 특히 중요합니다.** viewBox 가 축소되면 글자도 같이 줄어서,
390px 화면에서 9px 라벨은 4~5px 로 렌더링돼 읽을 수 없습니다.

### 내린 탭 — 코드는 남아 있습니다

| 내린 것 | 왜 |
|---|---|
| 괴리율 · 국내 본주 | 야간 대체가격. 분석의 본질이 아니라 참고용이었습니다 |
| DEX 선물 (하이퍼리퀴드) | 같음 |
| 지수 선물 | 같음 |
| ETF 프록시 | 같음 |

넷 다 **"코스피가 닫힌 동안 한국 시장이 어디로 가는가"** 라는 하나의 주제였고,
목적 기준 5개에 들어가지 않습니다. `config.SECTIONS_RETIRED` 에서 key 를 지우고
`TAB_ORDER` 에 넣으면 그대로 돌아옵니다 — 코드·테스트·데모가 전부 남아 있습니다.

섹션 key 는 `TAB_ORDER` · `SECTIONS_MERGED_INTO` · `SECTIONS_RETIRED` 중
**정확히 하나**에 있어야 하고, 테스트가 이를 검사합니다. 선언 없이 빠지면
화면에서 조용히 사라지기 때문입니다.

| ~~`^T10YIE`~~ | 야후 제공 여부 불확실해 제외 |

`verified=False` 로 남은 항목은 2차 자료에서만 확인된 것으로, 화면에 `티커 미검증`
배지가 붙습니다. 실행 환경에서 최종 확인하십시오:

```bash

```

`validate_tickers` 는 대체 심볼(`alt_symbols`)도 자동으로 시도하고 어느 심볼로
성공했는지 표시합니다. 가격이 타당한 걸 확인했으면 `verified=True` 로 바꾸면 배지가 사라집니다.

## 4. 괴리율 계산식 (탭에서 내림 — 코드는 보존)

```
본주환산가(KRW) = 해외가격 × 환율 ÷ (1단위당 본주 주수)
괴리율(%)       = (본주환산가 ÷ 국내본주가 − 1) × 100
```

예) 삼성전자 런던 GDR 1,200 USD, 환율 1,380원, 1 GDR = 보통주 25주, 본주 70,000원

```
본주환산가 = 1,200 × 1,380 ÷ 25 = 66,240원
괴리율     = (66,240 ÷ 70,000 − 1) × 100 = −5.37%
```

프리장/애프터장 가격이 있으면 그 가격을 우선 사용합니다 (야간 괴리율 추적이 주 용도).

**한계 1.** 국내 장 마감 중에는 본주 가격이 종가로 고정되므로, 괴리율이 실제 가격차가
아니라 "마감 이후 해외에서 벌어진 움직임"을 반영합니다.

**한계 2 — 이게 더 중요합니다.** SK하이닉스는 본주→ADR 전환이 발행주식수의 2.5% 로
제한되어 있고, 2026년 7월 ADR 발행으로 그 한도가 이미 소진된 상태입니다. 즉 괴리가
벌어져도 차익거래로 좁힐 수단이 막혀 있습니다. **괴리율이 크다는 사실 자체가 차익거래
기회를 뜻하지 않습니다.**

---

### 괴리율과 국내 본주를 합친 이유

전에는 두 탭이었습니다. 그런데 **둘은 같은 계산의 양쪽**입니다 — 국내 본주가는
괴리율의 분모고, 따로 보면 계산 사슬이 안 보입니다. 그래서 하나로 합치고
사슬을 왼쪽에서 오른쪽으로 펼쳤습니다:

```
해외가  ×  환율  ÷  환산주수  =  본주환산가   vs   국내 본주가   →   괴리율
$14.54   1,380      0.1        200,659원         196,000원        +2.38%
```

숫자 하나가 비면 **어디서 끊겼는지** 바로 보입니다. 끊긴 줄에는 사유가 붙습니다
(해외 시세 없음 / 본주 시세 없음 / 환율 없음 / 환산주수 미설정).

해외 상장이 없는 국내 종목(현대차)은 **"짝이 없는 국내 종목"** 으로 따로 묶습니다.
섹션 정의에서 `SECTIONS_MERGED_INTO` 로 합쳐졌다고 선언해 두었고, 테스트가
"섹션이 선언 없이 화면에서 사라지지 않는지" 를 검사합니다.

### 실시간 — 그리고 "실시간이 아닐 때" 를 말해줍니다

자동 갱신(기본 30초)으로 양쪽이 같이 새로고침됩니다. 화면 위에 배지 두 개가 있습니다:

| 배지 | 뜻 |
|---|---|
| 실시간 · 19:42:03 KST · 30초마다 갱신 | 갱신 주기와 마지막 갱신 시각 |
| 코스피 · 마감 후 · 본주가 종가로 고정 | **지금 괴리율의 성격** |

두 번째가 중요합니다. **코스피가 닫혀 있으면 괴리율은 실제 가격차가 아닙니다.**
본주가가 종가로 고정돼 있으니, 그 수치는 *마감 이후 해외에서 벌어진 움직임*을
본주 기준으로 환산한 값입니다. 야간에 보는 사람에게는 이 구분이 숫자보다
중요하므로, 장이 닫혀 있으면 경고를 띄웁니다.

장 상태 판정은 `compute.kospi_state()` 에 있습니다 — UI 가 아니라 도메인 로직이라
streamlit 없이도 테스트됩니다 (09:00~15:30 장중, 주말·개장전·마감후는 고정).

### 괴리율이 크다고 차익거래 기회가 아닙니다

- SK하이닉스 ADR 은 **본주→ADR 전환이 발행주식수의 2.5% 로 제한**되어 있어
  차익거래로 괴리가 좁혀지기 어렵습니다
- 세금·수수료·환전 비용이 이 수치에 반영되어 있지 않습니다
- 해외 종목에 프리/애프터장 가격이 있으면 **그걸 우선** 씁니다 (야간 괴리율이
  이 화면의 주 용도입니다)

## 5. 공시 분석 탭 — 버튼 하나로 스킬을 실행합니다

**대시보드에서 '분석 실행' 버튼을 누르면 Claude Code 가 백그라운드에서 실제 스킬을
돌려 결과를 채웁니다.** 복사·붙여넣기가 필요 없습니다.

### 어떻게 동작하나

Claude Code 는 `-p`(`--print`) 플래그를 주면 대화형 UI 없이 같은 에이전트 루프를
한 번 돌리고 결과를 출력한 뒤 종료합니다(헤드리스 모드). 커스텀 스킬은
파일시스템 기반(`~/.claude/skills/`)이라 API 업로드가 필요 없으므로, 이미 설치된
스킬을 그대로 씁니다.

```
[버튼 클릭]
   ↓
claude -p "/company-decoder-korean Micron (MU) … analysis/MU/decoder.html 에 저장"
        --output-format json --max-turns 40
        --permission-mode dontAsk
        --allowedTools "Read,Write,Edit,Bash,WebSearch,WebFetch,Glob,Grep"
   ↓
스킬이 웹검색·계산을 수행하고 HTML 을 지정 경로에 직접 저장
   ↓
[대시보드가 그 파일을 읽어 표시 · 비용·턴 수도 함께]
```

### 실행이 Streamlit 재실행에 영향받지 않는 이유

서브프로세스를 **분리(`start_new_session=True`)** 로 띄우고, 작업 상태를
`analysis/<키>/.jobs/<종류>.json` 에, 로그를 같은 폴더의 `.log` 에 씁니다.
UI 는 그 파일만 읽습니다. 그래서 위젯을 건드려 스크립트가 다시 실행되든,
브라우저를 닫든 작업은 계속 돌아가고 상태가 남습니다.

### 실행 전 확인

```bash
python -m tools.check_runner            # claude CLI·스킬 위치 점검
python -m tools.check_runner --dry-run  # 실제로 넘길 명령·프롬프트 출력
python -m tools.check_runner --jobs     # 저장된 작업 상태 전체 조회
```

**이 도구가 자동으로 알 수 없는 유일한 것은 슬래시 명령 이름입니다.**
플러그인으로 설치했으면 접두어가 붙습니다 — 예: `/anthropic-skills:company-decoder-korean`.
터미널에서 `claude` 실행 후 `/` 를 입력하면 정확한 이름이 보이고, 앱 사이드바의
**'분석 실행 설정'** 에서 바꿀 수 있습니다.

### 비용 — 반드시 보고 쓰십시오

실행마다 토큰을 씁니다. 기업 해독기 한 건이 웹검색 10회 이상 + 계산 + HTML 생성입니다.
완료된 작업의 `total_cost_usd` 를 화면에 그대로 표시하니 **첫 실행 비용을 보고
나머지를 판단하십시오.** `--max-turns`(기본 40) 로 상한을 둡니다. 사이드바에서 조절합니다.

### 자주 나는 실패와 조치

| 증상 | 원인·조치 |
|---|---|
| 버튼이 비활성 | `claude` 가 PATH 에 없음 → `npm install -g @anthropic-ai/claude-code` |
| "인증 실패" | 터미널에서 `claude` 한 번 실행해 로그인, 또는 `ANTHROPIC_API_KEY` 설정 |
| "html 이 생성되지 않았습니다" | 슬래시 명령 이름 불일치 → 사이드바에서 수정 |
| "도구 사용이 거부됐습니다" | `runner.py` 의 `DEFAULT_ALLOWED_TOOLS` 에 해당 도구 추가 |
| "턴 수에 걸려 중단" | 사이드바에서 최대 턴 수 상향 (비용도 올라감) |

앱은 실패 사유를 그대로 보여주지 않고 **조치 가능한 문장으로 번역**해서 띄우고,
실행 로그 꼬리도 함께 보여줍니다.

### 수동 경로도 남아 있습니다

claude CLI 를 쓸 수 없는 환경(예: Streamlit Cloud 배포본)에서는 '분석 실행' 이
동작하지 않습니다. 그때는 Claude 대화창에서 스킬을 돌려 받은 HTML 을
`analysis/<티커>/<종류>.html` 에 직접 넣으면 됩니다 — 화면에 경로를 안내합니다.

### 폴더 구조

```
analysis/
├── MU/
│   ├── meta.json      # {"name","generated","mode","sources":[],"note"}
│   ├── decoder.html   # company-decoder-korean 산출물
│   ├── story.html     # company-story-korean 산출물
│   └── price.html     # price-decoder-korean 산출물
├── 005930/
└── ...
```

`python -m tools.scaffold_analysis` 로 폴더와 `meta.json` 틀을 한 번에 만들 수 있습니다
(기존 파일은 덮어쓰지 않습니다). `.jobs/` 폴더는 실행 상태·로그가 쌓이는 곳으로,
지워도 분석 결과에는 영향이 없습니다.

`meta.json` 의 `mode` 는 `"web"`(웹검색 기반) 또는 `"filing"`(공시 원문 기반)입니다.
`generated` 가 90일을 넘으면 화면에 "오래됨" 경고가 뜹니다 — 그 사이 실적 발표가
있었다면 다시 실행해야 합니다.

### API 경로를 쓰지 않은 이유

Anthropic API 도 스킬을 지원합니다(`container.skills` + code execution 도구).
하지만 커스텀 스킬을 API 에 **따로 업로드**해야 하고(스킬은 서피스 간 동기화되지
않습니다), 웹검색 도구도 별도로 붙여야 하며 비용이 더 듭니다. Claude Code 헤드리스
경로는 이미 설치된 스킬을 그대로 쓰고 업로드 단계가 없어서 이쪽을 택했습니다.

## 6. 변화 감지 탭 — 대시보드의 본업

뉴스 피드가 아닙니다. **"무엇이 달라졌는가"** 만 봅니다.

| 신호 | 조건 | 심각도 |
|---|---|---|
| 새 공시 | 내 분석 생성일보다 최신인 10-K/10-Q/8-K/13D 등 | 30일 내 **지금**, 그 외 이번 주 |
| 실적 임박 | 발표 예정일이 14일 내 | 5일 내 **지금**, 그 외 이번 주 |
| 급등락 | 하루 등락률 ±5% 초과 | ±8% 초과면 **지금** |
| 52주 최저가 근처 | 저점 +3% 안 | 이번 주 |
| 분석 노후화 | 생성 후 90일 초과 | 이번 주 |
| 고점 대비 낙폭 | 25% 초과 | 참고 (37% 초과면 이번 주) |
| 분석 미생성 | 한 번도 안 돌림 | 참고 |

임계값은 `config.py` 의 `SIGNAL_*` 로 조절합니다.

### 받은편지함이 범람하지 않게

9종목이면 "분석 없음"이 9건 뜹니다. 그건 알림이 아니라 할 일 목록입니다. 그래서:

- **같은 종류의 '참고' 신호 3건 이상은 한 카드로 묶습니다** — "분석 미생성 8종목"
- **'지금'·'이번 주'만 펼쳐 보이고 '참고'는 접어 둡니다**
- 2건 이하는 묶지 않습니다 — 묶는 게 오히려 정보를 가립니다

데모 데이터 기준 **20건 → 8건**(펼침 6건 + 접힌 묶음 2건)으로 줄었습니다.

### 각 신호에 프롬프트가 붙습니다

대시보드가 판단을 내리는 대신, **판단이 필요한 순간과 그때 물어볼 질문**을 만듭니다.
새 공시가 감지되면 이런 프롬프트가 생성됩니다:

```
MU(Micron) 에 새 공시가 올라왔습니다: 10-Q(2026-11-02), 8-K(2026-10-27)
기존 분석 생성일: 2026-09-26

이 공시들을 반영해서 기존 분석 대비 달라진 점 중심으로 정리해 주세요.
특히 가이던스 변경, 리스크 요인 추가·삭제, 세그먼트별 추세 변화를 보고 싶습니다.
변화가 없으면 '변화 없음'이라고 해 주세요.
```

복사해서 Claude 에 붙여넣거나, claude CLI 가 있으면 '공시 분석' 탭에서 바로 실행합니다.

### SEC EDGAR — 키가 필요 없습니다

`data.sec.gov` 는 인증·API 키 없이 쓸 수 있고 공시 배포 즉시(보통 1초 내) 갱신됩니다.
다만 **SEC 는 키 대신 연락처가 담긴 User-Agent 를 요구**하고, 없으면 403 으로 거부합니다.

```python
# config.py — your-email 부분을 본인 주소로 바꾸십시오
EDGAR_USER_AGENT = "stock-dashboard/1.0 (personal research; your-email@example.com)"
```

초당 10건 한도가 있어 요청 간격을 0.15초로 벌려 두었습니다. 티커→CIK 매핑은
`company_tickers.json`(약 1MB)을 받아 24시간 캐시합니다.

**한국 종목은 EDGAR 에 없습니다** — DART 를 씁니다 (7절 참조).

### 뉴스는 보조입니다

장기투자자에게 헤드라인 20개는 노이즈입니다. 그래서 **공시나 급등락 신호가 잡힌
종목에만, 최대 4종목 × 3건**만 붙습니다. 노후화·미생성 신호에는 붙이지 않습니다.

소스는 미국 종목이 yfinance, 한국 종목이 구글 뉴스 RSS 로 둘 다 키가 필요 없습니다.
**제목과 링크만** 가져오며 본문은 가져오지도, 저장하지도 않습니다.

## 7. DART 연동과 재고 지표 (레이어 2)

한국 종목(삼성전자·SK하이닉스)의 **공시 감지**와 **재고 지표 계산**은 DART 오픈API 를
씁니다. EDGAR 와 달리 **키가 필요**하지만 무료입니다.

### 키 발급 — 5분

1. https://opendart.fss.or.kr 회원가입 (이메일 인증)
2. '인증키 신청/관리' → 신청
3. '오픈API 이용현황' 에서 40자리 키 확인
4. 환경변수로 설정하고 앱 재시작

```bash
export DART_API_KEY="40자리키"      # macOS/Linux
setx DART_API_KEY "40자리키"        # Windows (새 터미널부터 적용)
```

**키는 환경변수로만 받습니다.** `config.py` 에 적으면 압축 파일이나 저장소에 섞여
나갑니다. 호출 한도는 인증키당 하루 20,000건이고, 이 앱은 종목 2~3개만 조회하므로
근접할 일이 없습니다.

```bash
python -m tools.check_dart              # 키·고유번호·공시 점검
python -m tools.check_dart --no-call    # 키만 확인
python -m tools.check_dart --inventory  # 재고 지표까지 실제 계산
```

### 종목코드 ≠ 고유번호

DART 는 종목코드(005930)가 아니라 **8자리 고유번호(corp_code)** 로 기업을 식별합니다.
그래서 `corpCode.xml`(약 1MB ZIP)을 받아 `stock_code → corp_code` 로 변환한 뒤
호출하고, 24시간 캐시합니다. 삼성전자우(005935)처럼 우선주는 별도 종목코드지만 같은
법인이라, 매핑에 없으면 보통주 코드로 폴백합니다.

### 재고 지표 — 지표체계 v2 레이어 2

분기보고서에서 직접 계산합니다.

| 지표 | 계산식 |
|---|---|
| DIO | 기말 재고 ÷ 기간 매출원가 × 기간일수 |
| 재고-매출 갭 | 재고 증가율 − 매출 증가율 (직전 분기 대비, %포인트) |
| 재고 구성 | 원재료 / 재공품 / 완제품 비중 |

**DIO 절대값은 의미가 없습니다 — 자사 역사적 밴드 내 위치가 신호입니다.** 그래서
단일 분기가 아니라 5개 분기를 모아 밴드(최소·중간값·최대)와 현재 위치를 함께 보여줍니다.
②→③ 전환 체크리스트 중 재고 항목 3개를 자동 판정합니다.

### 메모리 3사를 한 화면에서 — 미국은 키가 필요 없습니다

삼성전자·SK하이닉스는 DART(키 필요), **마이크론(MU)은 EDGAR XBRL(키 불필요)** 로
가져옵니다. 두 경로가 **같은 `InventoryTrend` 타입**을 돌려주므로 화면·체크리스트·
신호 코드는 한국 기업과 미국 기업을 구분하지 않습니다.

| | 한국 2사 | 마이크론 |
|---|---|---|
| 소스 | DART `fnlttSinglAcntAll` | EDGAR `companyconcept` (XBRL) |
| 인증키 | 필요 (`DART_API_KEY`) | 불필요 (User-Agent 만) |
| 기간일수 | 보고서 종류로 추정 (분기 91.25일) | **구간 시작·종료일로 실제 계산** |
| 공시 시점 | 분기말 +45일 | 10-Q, 더 빠름 |

기간일수 차이가 실제로 중요합니다. 마이크론은 **53주 회계연도**를 쓰는 해가 있어
한 분기가 14주(97일)입니다. 91일로 고정하면 DIO 가 **8일 이상** 어긋납니다
(검증: FY2026 Q1 기준 실제일수 137.2일 vs 91일 가정 128.7일). XBRL 은 구간을
알려주므로 그대로 씁니다.

**DIO 계산 관행 주의 —** 이 앱의 DIO 는 `기말 재고 ÷ 기간 매출원가 × 구간 실제 일수`
입니다. 기업이 실적발표에서 직접 공시하는 DIO 와는 다를 수 있습니다. 기업은 보통
**평균 재고**를 쓰거나 **분기를 91일로 고정**하는 관행을 따릅니다. 여기 값은 3사를
**같은 방식으로 맞춘 비교용**이고, 단일 기업의 절대 수준을 볼 때는 회사 공시값이 더
적절합니다. 화면의 XBRL 패널 아래에 같은 문구를 각주로 달아두었습니다.

XBRL 쪽에서 신경 쓴 두 가지:

- **중복 보고 제거** — 같은 기간이 10-Q, 그 다음 10-K 비교란, 다음 해 10-K 에 반복
  실립니다. 값이 정정되기도 하므로 `(start, end)` 별로 **제출일(`filed`)이 가장 늦은
  것만** 남깁니다.
- **반기·누적 구간 배제** — 분기(60~120일) 구간만 씁니다. 반기 180일 구간이 분기로
  섞이면 DIO 분모가 두 배가 됩니다.
- **정렬은 종료일로** — 회계연도·분기 표기(`fy`/`fp`)로 정렬하면 `fp` 가 빈 건이 연도
  맨 앞으로 밀리고, `FY` 와 `Q4` 가 뒤섞이고, `fy` 없는 건은 종료일 연도로 대체되어
  회계연도와 어긋납니다(마이크론 FY2026 Q1 은 2025-12 종료). 종료일은 항상 있고 항상
  단조증가하므로 그쪽을 씁니다.

### 계정 매칭 — 가장 깨지기 쉬운 지점

`account_nm == "매출액"` 으로 필터링하면 절반이 빈 값으로 빠집니다. 기업마다 계정명을
다르게 씁니다(매출액 / 수익(매출액) / 영업수익).

그래서 **XBRL 표준계정ID(`ifrs-full_Revenue`, `ifrs-full_Inventories`,
`ifrs-full_CostOfSales`)를 1순위**로 맞추고, 표준ID 가 없을 때만 계정명 후보로
폴백합니다. 재무제표 구분(BS/IS)도 함께 걸러서 현금흐름표의 '재고자산의 변동' 같은
동명 계정을 집지 않습니다. 둘 다 실패하면 **숫자를 추정하지 않고** 어느 계정을
못 찾았는지 화면에 표시합니다.

### 기간 불일치 가드

분기 손익계산서의 `thstrm_amount` 는 **3개월 금액**, `thstrm_add_amount` 가 누적입니다.
이게 어긋나면 DIO 가 폭발합니다 — 분기 금액에 365일을 적용하면 730일이 나옵니다.

그래서 DIO 가 타당 범위(5~400일)를 벗어나면 **그 분기를 버리고 경고를 남깁니다.**
밴드가 이상값 하나로 전부 왜곡되는 걸 막는 장치입니다. 실제 DART 응답에서 기간이
어긋나도 같은 가드가 걸립니다.

### 분기보고서는 실적 발표보다 늦습니다

기업은 분기말 후 2~4주에 잠정실적을 발표하지만, **재고자산 주석이 담긴 분기보고서는
45일 뒤**(사업보고서는 90일)에 나옵니다. 그래서 재고 지표의 기준 분기는 헤드라인
실적보다 한 분기 뒤처질 수 있습니다. 그게 맞습니다 — 없는 보고서를 조회하면
상태 013 입니다. 앱은 013 을 정상으로 보고 한 분기 물러서며 수집합니다.

### 실제 데이터로 확인해야 할 것 — 진단 스크립트

이 코드는 **샌드박스에서 실제 응답을 한 번도 받아본 적이 없습니다.** DART·SEC 가 모두
차단된 환경에서 만들었습니다. 그래서 다음 네 가지는 수빈님 컴퓨터에서만 답이 나옵니다:

```bash
python -m tools.diagnose              # 전체
python -m tools.diagnose --xbrl       # 키 없이 MU 만 (바로 실행 가능)
python -m tools.diagnose > report.txt
```

출력이 답해주는 것:

1. **재고 구성 계정이 실제로 응답에 있나** → 있으면 체크리스트 3번째 항목이 살아납니다
2. **DIO 가 타당 범위(5~400일)에 들어오나** → 가드가 걸리면 기간 처리를 고쳐야 합니다
3. **어느 태그/계정명이 실제로 쓰이나** → 후보 목록 순서를 조정합니다
4. **계산 DIO vs 91일 가정** → 회사 공시값과 어느 쪽이 가까운지

출력에 인증키는 들어가지 않습니다(끝 4자리만). **출력을 그대로 복사해 Claude 에
붙여넣으면** 결과에 맞춰 코드를 고칠 수 있습니다.

### 알려진 한계

- **재고 구성(원재료·재공품·완제품)은 주석 항목**이라 전체 재무제표 API 에 없는 경우가
  많습니다. 그때는 '판정 불가' 로 두고, 보고서 원문을 봐야 한다고 표시합니다.
  마이크론도 `InventoryRawMaterialsAndSuppliesNetOfReserves` 등을 보고하지 않는
  분기가 있어 같은 처리를 합니다.
- **4분기 단독 수치는 관측되지 않습니다.** 사업보고서는 연간 금액이라 FY DIO 는
  연간 평균 성격입니다.
- **재무정보 API 는 2015년 이후만** 제공합니다.
- 레이어 1(가격)·3(CapEx)·4(수요)는 공시에서 계산할 수 없어 다루지 않습니다.
  이 탭은 레이어 2 전용이고, 판정은 가격 레이어와 교차검증해야 합니다.

## 8. 매크로 탭 — 뉴스 피드가 아닙니다

### 왜 피드로 만들지 않았나

일반 매크로 뉴스 피드는 §6에서 고친 **받은편지함 범람** 문제를 그대로 되풀이합니다.
헤드라인 30개를 띄우면 그중 무엇이 수빈님 포트폴리오와 관련 있는지 다시 사람이
걸러야 합니다. 그래서 티커 쪽과 **같은 규율**을 씁니다:

```
지표가 임계값을 건드렸을 때만 → 신호를 내고 → 그 신호에만 뉴스를 붙입니다
```

평소에는 숫자만 조용히 보여줍니다. "임계값에 닿은 지표가 없습니다"가 정상 상태입니다.

### 가격과 통계를 분리합니다

| | 소스 | 성격 | 지연 |
|---|---|---|---|
| 10년물 금리, 환율, VIX, 유가, 금 | 야후 | **시장가격** | 실시간 |
| CPI, 코어 PCE, 고용, 산업생산, PPI | FRED | **통계** | 2~6주 |

이걸 섞으면 "어제 CPI" 같은 착각이 생깁니다. 그래서 화면에서도 위아래로 나누고,
통계에는 **관측 시점과 지연일수**를 항상 붙입니다. FRED 는 인증키가 필요 없습니다 —
API 는 키를 요구하지만 CSV 내보내기 경로(`fredgraph.csv?id=...`)는 키 없이 열립니다.

### 보는 지표와 그 이유

**금리·신용** — O(리츠)·SCHD·QQQ 밸류에이션에 직결

| 지표 | 계열 | 임계값 | 왜 |
|---|---|---|---|
| 10년 국채 금리 | `DGS10` | 20영업일 ±0.50%p | 할인율의 기준. O는 역방향, QQQ는 듀레이션이 길어 더 민감 |
| 2년 국채 금리 | `DGS2` | 20영업일 ±0.50%p | 연준 정책 기대를 가장 직접 반영 |
| 10년-2년 스프레드 | `T10Y2Y` | **부호 전환** | 역전 진입도 신호지만 역전에서 **되돌아올 때**가 더 중요한 국면이었음 |
| 하이일드 스프레드 | `BAMLH0A0HYM2` | 20영업일 ±1.00%p | 신용 스트레스의 조기 경보 |

**인플레이션** — 금리 경로를 결정

| 지표 | 계열 | 임계값 | 왜 |
|---|---|---|---|
| CPI | `CPIAUCSL` | 전년대비 ±0.3%p | 헤드라인. 에너지·식품이 섞여 변동이 큼 |
| 코어 CPI | `CPILFESL` | 전년대비 ±0.3%p | 추세 물가 |
| 코어 PCE | `PCEPILFE` | 2.5% 상회 / ±0.2%p | **연준의 공식 목표 지표** |
| 5년후 5년 기대인플레 | `T5YIFR` | 2.5% 상회 / 1.8% 하회 | 시장이 보는 장기 기대 |

**고용·경기**

| 지표 | 계열 | 임계값 | 왜 |
|---|---|---|---|
| 주간 실업수당 청구 | `ICSA` | 4주 평균 대비 ±15% | **주간으로 나오는 가장 빠른 지표**, 월간 고용보다 3~6주 앞섬 |
| 실업률 | `UNRATE` | 3개월 ±0.3%p | 저점 대비 0.3%p 상승은 과거 침체의 공통 패턴 (Sahm rule 근사) |
| 비농업 고용 | `PAYEMS` | 전월 대비 마이너스 | 마이너스 전환은 명확한 신호 |

**반도체 사이클** — 지표체계 v2 의 레이어 1·4 대리

| 지표 | 계열 | 임계값 | 왜 |
|---|---|---|---|
| 반도체 산업생산 | `IPG3344S` | 전년대비 **부호 전환** | 미국 반도체·전자부품 실물 생산량 (NAICS 3344) → 레이어 4(수요) 대리 |
| 반도체 생산자물가 | `PCU334413334413` | 전년대비 **부호 전환** | 반도체 제조업 출하 가격 → **레이어 1(가격) 대리** |

마지막 두 개가 이 탭을 만든 실질적 이유입니다. 수빈님 지표체계에서 레이어 1·3·4는
"공시에 없어 계산할 수 없다"고 적어둔 층인데, **키 없이 얻을 수 있는 공적 계열**이
여기 있습니다. DRAM 현물가의 대체는 못 되지만 방향은 읽힙니다.

### 지수는 레벨을 쓰지 않습니다

산업생산·PPI 같은 지수 계열은 **기준연도가 바뀝니다** — 같은 `IPG3344S` 가
"2017=100" 으로도 "2022=100" 으로도 나옵니다. 그래서 레벨은 버리고 **전년 동기
대비**만 씁니다. 변화율은 기준연도와 무관하고, 테스트가 그걸 검증합니다.

### 색으로 좋고 나쁨을 말하지 않습니다

가격 카드는 한국 관행대로 상승 적색·하락 청색입니다. 매크로 지표에는 그 색을
쓰지 않았습니다 — **실업률 상승과 반도체 생산 상승은 의미가 반대**이므로, 색으로
방향을 칠하면 틀린 신호를 줍니다. 방향은 ▲▼ 기호와 숫자로만 표시하고, 색은
"임계값을 건드렸다"에만 씁니다.

### 임계값은 제 판단입니다

위 표의 숫자는 제가 정한 것이고, 근거는 각 계열의 `why` 필드에 적어 화면에도
띄웁니다. 수빈님 판단과 다르면 `config.py` 의 `MACRO_SERIES` 에서 바꾸십시오.
임계값을 전부 `None` 으로 두면 신호 없이 표시만 합니다.

### 계열 ID 검증이 필요합니다

13개 계열 중 **6개만 이 세션에서 실제로 확인**했습니다
(`DGS10` `CPIAUCSL` `UNRATE` `PAYEMS` `IPG3344S` `PCU334413334413`).
나머지 7개는 제 기억에서 쓴 것이고, **틀린 ID 는 404 로 조용히 비어 보입니다.**
화면에 "계열 미검증" 으로 표시해 두었고, 한 번 돌리면 정리됩니다:

```bash
python -m tools.diagnose --fred
```

'신규✓' 로 나온 계열은 `config.py` 에서 `verified=True` 로 바꾸십시오.
'✗' 는 ID 가 틀린 것이니 fred.stlouisfed.org 에서 찾아 고치십시오.

## 9. 공포탐욕지수 — 한 숫자가 아니라 7개 세부 지표

매크로 탭에 CNN 공포탐욕지수(Fear & Greed Index)를 넣었습니다. 시장가격과
경제통계 사이에 둡니다 — **가격도 통계도 아닌 제3의 성격**(심리)이기 때문입니다.

### 세부 지표를 함께 보여주는 이유

지수는 0~100 한 숫자지만, 그것만 보면 **왜 그 값인지 알 수 없습니다.** 같은
"탐욕 70" 이 주가 모멘텀 때문인지 채권 수요 때문인지는 전혀 다른 이야기입니다.
그래서 7개 세부 지표를 함께 띄우고, **극단(25 미만 또는 75 이상)에 있는 것**을
따로 뽑아 "지금 지수를 끌고 있는 것" 으로 적습니다.

| 세부 지표 | 무엇을 보는가 |
|---|---|
| 주가 모멘텀 | S&P 500 이 125일 이동평균 위/아래 어디에 있나 |
| 주가 강도 | 52주 신고가 종목 수 vs 신저가 종목 수 |
| 거래량 폭 | 상승 종목 거래량 vs 하락 종목 거래량 |
| 풋/콜 비율 | 하락 베팅이 상승 베팅보다 많은가 |
| 변동성(VIX) | VIX 가 50일 이동평균 대비 어디에 있나 |
| 안전자산 수요 | 주식 수익률 vs 국채 수익률 — 돈이 어디로 가나 |
| 하이일드 수요 | 정크본드와 국채의 수익률 격차 — 위험 선호도 |

구간은 CNN 기준입니다: 25 미만 극단적 공포 · 45 미만 공포 · 55 미만 중립 ·
75 미만 탐욕 · 그 이상 극단적 탐욕. 게이지에 경계를 눈금으로 찍어 위치를
보이게 했습니다.

### 숫자가 안 맞을 때 — 확인 순서

**1. 데모 모드인지 먼저 보십시오.** 프리뷰 아티팩트는 **전부 데모 데이터**이고,
앱에서도 사이드바 데모 모드가 켜져 있으면 가짜 숫자가 나옵니다. 데모 공탐지수는
**63 고정**입니다.

데모 숫자를 그럴듯하게 만들어 둔 탓에 실제 값과 구분할 방법이 없었습니다.
그래서 **데모일 때 모든 탭 맨 위에 경고 배너**를 띄웁니다:

```
⚠ 지금 보이는 숫자는 전부 가짜입니다
공포탐욕지수·VIX·주가·재고·재무 — 어느 것도 실제 값이 아닙니다
```

**2. CNN 공식 페이지와 대조하십시오.** 공탐 섹션 아래에 링크를 넣었습니다.

**3. 다르면 진단을 돌려 알려주십시오.** 사이드바 → 진단 → 경제지표 확인이
이제 **응답의 실제 키 목록**을 찍습니다:

```
응답 최상위 키: fear_and_greed, fear_and_greed_historical, market_momentum_sp500, ...
fear_and_greed 키: score, rating, timestamp, previous_close, ...
⚠ 못 읽은 비교값: previous_1_week — 키 이름이 바뀌었을 수 있습니다
⚠ 관측일이 12일 전입니다 — 타임스탬프 해석이 틀렸을 수 있습니다
```

이 출력을 붙여주시면 파싱을 실제 구조에 맞출 수 있습니다.

### 파싱을 단정하지 않습니다

문서가 없는 엔드포인트라 **형식을 확정할 수 없습니다.** 그래서:

- **타임스탬프**: 밀리초·초·ISO 문자열을 모두 받고, 결과가 **상식 범위
  (2000년 이후 ~ 내일)** 를 벗어나면 비웁니다. 틀린 날짜를 보여주는 것보다
  비우는 게 낫습니다
- **키 이름**: `score`/`value`, `rating`/`label`, `previous_1_week`/
  `previous_week`/`previous1Week` 등 후보를 순서대로 봅니다
- **비교값을 못 읽어도** 점수는 살립니다 (해당 칸만 비움)

### 출처 주의 — 공개 API 가 아닙니다

```
https://production.dataviz.cnn.io/index/fearandgreed/graphdata/{시작일}
```

CNN 이 **자기 페이지에서 호출하는 내부 엔드포인트**입니다. 문서가 없고 예고 없이
바뀌거나 막힐 수 있습니다. 그래서:

- 실패를 **정상 경로로 취급**합니다 — 예외를 던지지 않고 `error` 가 담긴 객체를
  돌려주므로, 이것 때문에 매크로 탭의 다른 지표가 비지 않습니다
- 사이드바 진단의 '경제지표 계열 확인' 에 **엔드포인트가 아직 열려 있는지**
  확인하는 항목을 넣었습니다
- User-Agent 를 안 보내면 거부됩니다

**이 지수는 심리 지표이고 가치 판단이 아닙니다** — 탐욕 구간이라고 비싸다는
뜻이 아닙니다.

## 10. VIX — 숫자 하나가 아니라 곡선의 모양

### VIX 18 이 높은가?

맥락 없이는 답할 수 없습니다. DIO 에서 "절대값은 의미 없고 자사 밴드 내 위치가
신호" 라고 했던 것과 **같은 문제**입니다. VIX 는 매크로 가격 카드에 원래 있었지만
숫자만 떠 있어서 쓸모가 없었습니다. 두 가지를 붙였습니다.

### 1. 과거 대비 백분위

FRED `VIXCLS` 일별 종가 5년 이력으로 백분위를 냅니다.

```
현재 VIX 16.40 는 5년 관측치의 20% 지점입니다 (1년 기준 20%).
5년 범위는 15.0 ~ 39.9 이고, 1년 중간값은 18.7 입니다.
```

"VIX 16.4" 보다 "5년 중 하위 20%" 가 판단에 쓰입니다. FRED 라 키가 필요 없습니다.

### 2. 기간구조 — 이쪽이 더 중요합니다

Cboe 는 만기별로 여러 지수를 냅니다:

```
VIX9D (9일)  →  VIX (30일)  →  VIX3M (3개월)  →  VIX6M (6개월)
```

평소에는 뒤로 갈수록 높습니다(**콘탱고** = 평온). 위기에는 앞이 치솟아 뒤보다
높아집니다(**백워데이션** = 시장이 지금 당장을 더 두려워함).

핵심 비율은 **IVTS = VIX ÷ VIX3M** 입니다:

| 비율 | 판정 | 뜻 |
|---|---|---|
| < 0.90 | 강한 콘탱고 | 평온한 구간의 전형 |
| 0.90 ~ 1.00 | 콘탱고 (평평) | 역전 쪽을 주시할 값 |
| ≥ 1.00 | **백워데이션 (역전)** | 근월 스트레스 |

**역전은 2010년 이후 전체 거래일의 7.7% 에만 나타났습니다** (4,163일 중 322일).
드물기 때문에 신호가 됩니다. 화면에 이 기준값을 함께 적어서, 역전이 보일 때
"흔한 일인가" 를 되묻지 않게 했습니다.

`VIX9D ÷ VIX` 도 함께 봅니다. 이게 1.0 을 넘으면 **초단기만** 역전된 것인데,
FOMC·CPI 같은 예정된 이벤트 직전에 흔한 모양입니다. 구조적 스트레스와 구분해야
하므로 그 경우에만 따로 문구가 뜹니다.

곡선은 표가 아니라 **선으로** 그립니다 — 숫자 네 개를 표로 보면 모양이 안
보이고, 기울기가 신호이기 때문입니다. 현재 VIX 위치에 수평 점선을 깔아 뒤 만기가
위/아래인지 바로 읽히게 했습니다.

### 국면 지표이고 타이밍 도구가 아닙니다

화면에도 적어 두었습니다. **역전이 왔다고 팔 때라는 뜻이 아니고, 콘탱고라고
안전하다는 뜻도 아닙니다.** 경계값(0.90·1.00)은 관행이고 법칙이 아닙니다.

### 계열 검증 상태

`^VIX` 만 이 세션에서 확인했습니다. `^VIX9D`·`^VIX3M`·`^VIX6M` 은 야후에서
간헐적으로 비는 경우가 있어 **곡선에 '미검증' 으로 표시**됩니다.
**VIX3M 이 없으면 기간구조를 판정할 수 없고**, 그 경우 '판정 불가' 로 두고
무엇이 빠졌는지 경고합니다 — 비율을 추정하지 않습니다.

## 11. 52주 발굴 — 모멘텀과 품질을 교차합니다

### 먼저 분명히 해둘 것

**52주 신고가는 모멘텀 지표입니다.** "좋은 주식" 이 아니라 "최근 많이 오른 주식"
입니다. 신고가인 이유가 비싸서일 수도 있습니다. 수빈님이 평소 기술적 지표를
쓰지 않으시는 것과 성격이 다른 지표라, 단독으로 쓰지 않고 **버핏식 품질 기준과
교차**합니다.

|  | 52주 고가권 (구간 80%+) | 52주 저가권 (구간 20%−) |
|---|---|---|
| **품질 기준 통과** | ① 좋은 사업 + 오름세 | ③ 좋은 사업 + 눌림 |
| **품질 기준 미달** | ② 모멘텀만 | ④ 양쪽 다 미달 |

**③ 이 가치투자가 전통적으로 찾는 자리**이고, ① 은 시장이 이미 알아본 자리입니다.
어느 쪽이 맞는지는 이 숫자로 답할 수 없습니다 — 위치만 보여줍니다. 칸마다
다음에 물어볼 질문이 다릅니다:

- ① → 주가가 오른 **이유가 공시에 있는지**, 일회성인지 구조적인지
- ③ → **눌린 이유가 공시에 있는지** (Risk Factors 변화), 시장이 먼저 본 것이 있는지

### 구간 위치로 판정합니다 — '저가 대비 +N%' 가 아닙니다

처음엔 "52주 저가 대비 +20% 이내 = 저가권" 으로 했는데 **버그였습니다.**
52주 변동폭이 좁은 종목은 구간 중간에 있어도 저가권으로 잡힙니다 — 변동폭이
20% 인 종목은 구간 50% 지점이 "저가 대비 +10%" 라서 조건을 통과합니다.

데모에서 O(리츠)가 구간 50% 인데 저가권으로 분류돼 발견했습니다. 이제
**구간 위치**(저가~고가에서 몇 %)로 판정합니다 — 변동폭이 좁은 종목과 넓은
종목을 같은 자에 올립니다.

| 상태 | 기준 |
|---|---|
| 신고가 돌파 | 52주 고가의 99.5% 이상 |
| 고가권 | 구간 위치 80% 이상 |
| 저가권 | 구간 위치 20% 이하 |
| 신저가 | 구간 위치 0% 이하 (저가를 깬 상태) |

### 사분면이 비어 보이는 경우를 구분해서 말합니다

사분면은 **두 축이 모두 있어야** 분류됩니다. 52주 데이터는 시세에서 바로 오지만
품질은 10년치 재무가 필요해서, 재무 조회가 실패한 종목은 분류되지 않습니다.

품질 축이 있는 종목이 절반 미만이면 **"지도가 비어 보이는 이유"** 를 화면에
띄웁니다 — 해당하는 종목이 없다는 뜻이 아니라 재무를 못 받았다는 뜻이기
때문입니다. 이 구분이 없으면 "③ 에 아무것도 없네" 를 잘못 읽습니다.

## 12. 버핏식 스크리닝

### 하는 일과 하지 않는 일

**하는 일:** 10년치 공시 숫자로 **읽어볼 만한 후보**를 줄입니다.
**하지 않는 일:** 무엇을 살지 판단하지 않습니다.

버핏 기준의 핵심인 **경제적 해자, 경영진의 질, 내가 이해하는 사업인가**는
숫자로 걸러지지 않습니다. 숫자가 좋은데 해자가 없는 회사가 많고, 그 구분은
10-K 와 어닝콜을 읽어야 압니다. 그래서 흐름을 이렇게 잡았습니다:

```
스크리닝 (숫자)  →  후보 10~20개  →  이미 있는 스킬 3종으로 정독
                                     (기업 해독기 · 스토리 · 가격 판독)
```

각 카드에 **그 다음에 물어볼 질문**이 붙어 있습니다. 접은 부분을 펴서 Claude 에
붙여넣으면 정독이 시작됩니다. **점수가 높다고 좋은 투자가 아닙니다** — 읽는
순서를 정하는 용도입니다.

### 출처를 세 가지로 구분합니다

버핏의 "숫자 기준" 은 인용되는 과정에서 조금씩 변형됩니다. 그래서 각 기준에
출처를 표시했습니다. 화면의 토글을 켜면 전부 보입니다.

| 표시 | 뜻 | 바꿔도 되나 |
|---|---|---|
| **버핏 원문** | 주주서한에 직접 쓴 정의·규칙 | 바꾸면 다른 지표가 됩니다 |
| 인용 관행 | 그의 사례에서 널리 인용되는 수치. 원문 표현은 아님 | 바꿔도 됩니다 |
| 제 기준 | 자동화를 위해 제가 정한 구현 기준 | 바꿔도 됩니다 |

### 기준 6종

| 기준 | 출처 | 보는 방법 |
|---|---|---|
| ROE 꾸준히 높은가 | 인용 관행 | 10년 중 8년 이상 15% 넘었나 |
| **주주이익이 플러스인가** | **버핏 원문** | 순이익 + 감가상각 − 설비투자, 10년 중 8년 |
| **설비투자가 감가상각을 넘지 않는가** | **버핏 원문** | 넘은 해가 3년 이하인가 + 배수 |
| 부채가 적은가 | 인용 관행 | 장기부채/자본 0.5 이하 **또는** 순이익 4년치 이하 |
| 마진이 안 흔들리는가 | 인용 관행 | 매출총이익률 10년 표준편차 ±5%p 이하 |
| 이익이 꾸준한가 | 제 기준 | 적자·30% 이상 감익이 1회 이하 |

**주주이익 (1986년 버크셔 주주서한 부록)** — 원문 정의:

> (a) 보고 순이익 + (b) 감가상각·감모·무형자산상각 등 비현금 비용
> − (c) 사업이 장기 경쟁력과 판매량을 온전히 유지하기 위해 필요한 연평균 설비투자액

**결정적인 한계:** (c)는 **유지 설비투자**이고, 이건 공시되지 않습니다.
버핏 본인이 같은 글에서 "(c)는 추정이어야 하고, 때로는 매우 어려운 추정" 이라고
적었습니다. 이 앱은 **총 설비투자**를 대입하므로 성장 투자가 많은 기업의
주주이익은 **과소평가**됩니다. 자동화할 수 없는 부분이 여기입니다.

**설비투자 > 감가상각** — 같은 서한의 원문: "(c)가 (b)를 넘을 때 GAAP 이익은
주주이익을 과대계상한다. 그런 과대계상은 흔히 상당하다." 자본집약 사업을
걸러내는 직접 기준입니다. 다만 성장기 기업은 당연히 넘기 때문에, 횟수와 함께
**설비투자/감가상각 배수**를 같이 보여줍니다 — 1.1배와 2.5배는 같은 "초과" 지만
의미가 전혀 다릅니다.

### 거짓 통과를 막는 장치

거짓 탈락보다 **거짓 통과**가 위험합니다. 데이터가 없어서 좋아 보이는 경우입니다.
개발 중 실제로 두 건이 나왔습니다:

**1. 리츠의 마진이 ±0.0%p 로 "완벽하게 안정적"** — 리츠·금융은 매출원가를 따로
쓰지 않아 매출총이익 = 매출이 됩니다. 그러면 마진이 100% 로 고정되고 표준편차가
0 이 되어 통과합니다. 이제 **매출총이익이 매출과 같으면 판정 불가**로 둡니다.

**2. 리츠의 주주이익이 순이익의 269%** — 부동산 감가상각은 거대한데 자산 취득은
`PaymentsToAcquirePropertyPlantAndEquipment` 에 잡히지 않아 재투자가 과소계상됩니다.
통과시키되 **경고를 붙입니다.**

**판정 불가는 탈락이 아닙니다.** 점수는 `4 / 6` 처럼 표시하고 판정 불가 수를
따로 적습니다 — 데이터가 없는 것을 통과로도 탈락으로도 세지 않습니다.

### 기준별 통과율을 함께 봅니다

화면 위에 각 기준의 통과율이 나옵니다. **0% 나 100% 에 가까운 기준은 구분을
못 하고 있다는 뜻**이니 기준선을 조정할 후보입니다. 예를 들어 "설비투자 >
감가상각" 은 데이터센터·반도체 투자가 많은 현재 시장에서 거의 모든 성장 기업을
탈락시킵니다 — 기준이 틀린 게 아니라 **그 기준이 그 업종과 맞지 않는 것**입니다.

### 국내는 기준선을 따로 둡니다 — 이게 중요합니다

미국 기준(ROE 15% 이상 10년 중 8년)을 한국 종목에 그대로 적용하면 **거의 전부
탈락합니다.** 기업이 나빠서가 아니라 한국 상장사의 ROE 분포가 구조적으로 낮기
때문입니다(지배구조·낮은 배당성향·순환출자 등). 그대로 쓰면 "한국 주식은 다
안 좋다" 는 결론이 나오는데, **그건 기준이 틀린 것입니다.**

| 기준 | 미국 | 국내 |
|---|---|---|
| ROE | 15% 이상 / 10년 중 8년 | **10% 이상 / 7년** |
| 장기부채/자본 | 0.5 이하 | **0.6 이하** |
| 순이익 대비 부채 | 4년치 이하 | **5년치 이하** |
| 마진 표준편차 | ±5%p 이하 | **±7%p 이하** (수출 비중이 커 변동이 큼) |
| 설비투자 > 감가상각 | 3년 허용 | **4년 허용** (제조업 비중) |
| 적자·급감 | 1회 허용 | **2회 허용** |

국내 기준은 **버핏의 숫자가 아니라 제가 분포를 보고 정한 값**입니다. 화면에
'제 기준' 으로 표시되고 `buffett_kr.KR_THRESHOLDS` 에서 바꿀 수 있습니다.

### 국내는 계정 체계와 요청 방식이 다릅니다

| | 미국 | 국내 |
|---|---|---|
| 소스 | EDGAR companyfacts | DART `fnlttSinglAcntAll` (사업보고서) |
| 인증키 | **불필요** | **필요** |
| 1회 요청 범위 | 전 계정 · 전 기간 | 전 계정 · **3년** (당기·전기·전전기) |
| 10년 수집 | 1회 | **4회** (3년 간격, 겹치는 구간은 재작성 반영) |
| 계정 매칭 | us-gaap 태그 후보 | K-IFRS ID → **계정명 폴백** |

한국 공시는 계정명이 상당히 표준화되어 있어(매출액·매출원가·당기순이익·
자본총계) **이름 폴백이 미국보다 잘 듣습니다.** 다만 K-IFRS 계정 ID 는
**전부 미검증**입니다 — 진단 탭에서 확인해야 합니다.

같은 연도가 여러 보고서에 나오면 **최신 보고서 값을 씁니다** (재작성 반영).

### 대상 종목

미국: 관심종목(미국 개별주) + `config.py` 의 `SCREEN_CANDIDATES` 68개.
국내: 관심종목(국내) + `SCREEN_KR_CANDIDATES` 30개 (KOSPI 대형주).
둘 다 **추천 목록이 아닙니다.**
업종별로 넓게 깔아둔 것이고 **추천 목록이 아닙니다.** 티커만 추가하면 됩니다.

제외되는 것:

- **ETF·펀드** (QQQ, SCHD 등) — 사업 재무제표가 없어 ROE·마진이 의미 없습니다
- **한국 종목** (삼성전자, SK하이닉스) — SEC 에 신고하지 않아 이 경로로는 안 됩니다.
  한국 종목은 DART 기반으로 따로 만들어야 합니다

### 왜 companyfacts 인가

| 엔드포인트 | 범위 | 68개 기업 요청 수 |
|---|---|---|
| `companyconcept` | 1기업 × 1계정 | 68 × 12 = 816회 |
| **`companyfacts`** | 1기업 × 전 계정 | **68회** |

초당 10건 제한이 있어 816회는 80초, 68회는 7초입니다. 대신 응답이 커서
(대기업은 수 MB) 받는 즉시 필요한 계정만 뽑고 버립니다. 캐시는 24시간입니다 —
연간 재무제표는 1년에 한 번 바뀝니다.

### 확인이 필요합니다

이것도 실제 응답을 받아본 적이 없습니다:

```bash
python -m tools.diagnose --screen     # 앞 8개 기업만, 키 불필요
```

**'못 찾은 계정' 이 많으면** `buffett.TAGS` 의 태그 후보를 늘려야 합니다.
기업마다 같은 항목에 다른 us-gaap 태그를 쓰기 때문입니다.

## 13. 가격 판독과 판단 재료 — 추천을 하지 않는 이유

### 적정주가가 아니라 요구 성장률

```
적정주가 계산:  성장률을 가정 → 주가를 구함   (가정이 답을 결정합니다)
역DCF:         주가를 입력   → 성장률을 구함  (시장의 기대가 드러납니다)
```

적정주가는 할인율과 성장률을 조금만 바꿔도 원하는 숫자가 나와서 판단 재료가
못 됩니다. 그래서 방향을 뒤집습니다. 나온 숫자를 **과거 실제와 비교**하면
판단이 섭니다:

```
현재 가격이 요구하는 성장률   연 14%
과거 9년 실제                연 6%
격차                        +8%p
→ 시장은 과거보다 빠른 성장을 가격에 넣어두었습니다.
  그게 가능한 이유가 공시에 있는지는 읽어야 압니다.
```

**입력값의 출처가 중요합니다.** FCF 와 순부채는 **공시에서 자동으로** 나옵니다
(스크리너가 이미 10년치를 갖고 있습니다). 외부에서 오는 건 **시가총액 하나**뿐이고,
그것만 yfinance 에서 받습니다. 추정값은 없습니다.

### 가정 세 개 — 그래서 점이 아니라 구간

| 가정 | 기본값 | 왜 |
|---|---|---|
| 예측 기간 | 10년 | 그 이후는 영구성장으로 처리 |
| 영구성장률 | 2.5% | 장기 명목성장률 수준 |
| **할인율** | 8 / 10 / 12% | **가장 민감한 가정** — 셋을 모두 보여줍니다 |

할인율 8%와 12%에서 요구 성장률이 크게 달라집니다 (예: 연 15% vs 25%).
그래서 단일 숫자로 표시하지 않고 **구간**으로 씁니다.

### 적용할 수 없는 경우를 분명히 말합니다

역DCF 가 안 되는 기업이 꽤 있습니다. 그때 억지로 숫자를 내지 않습니다:

| 상황 | 처리 |
|---|---|
| FCF 가 0 이하 | **적용 불가** — 양의 현금흐름이 전제입니다 |
| 순현금 > 시가총액 | **적용 불가** — EV 가 음수가 됩니다 |
| 요구 성장률이 −50~60% 밖 | **적용 불가** — 가격이 현금흐름으로 설명되지 않습니다 |
| 사이클 왜곡 | **전용 메시지** + 지표체계로 되돌려보냄 |

**사이클 왜곡이 가장 까다롭습니다.** 최근 FCF 가 3년 평균에서 40% 이상 벗어나면
평균을 기준값으로 쓰는데(피크/트로프 왜곡 방지), 적자 연도가 섞인 사이클 업종은
평균이 최근값의 몇 % 수준으로 내려갑니다. 그러면 요구 성장률이 비현실적으로
높게 나옵니다. 두 갈래로 나눠 처리합니다:

- **역산이 아예 안 되면** → 적용 불가 + 사유 설명
- **역산이 "성공" 하면** → 이게 더 위험합니다. 에러 없이 그럴듯한 숫자가
  나와서 그냥 읽히기 때문입니다. 기준값이 최근의 절반 미만이면
  `severe_distortion` 플래그를 세우고 **"이 숫자를 그대로 쓰지 마십시오"** 를
  경고 맨 앞에 붙입니다.

MU 가 전자, 전형적인 사이클 종목이 후자에 걸립니다.

### 추천 대신 사분면

**"삼성전자 사세요" 는 왜 그런지 설명이 안 되면 따라갈 수 없고, 설명이 되면
추천이 필요 없습니다.** 그래서 두 축을 교차해 지금 어디에 서 있는지만
보여주고 결론은 비워둡니다.

|  | 요구 ≤ 과거 실제 | 요구 > 과거 실제 |
|---|---|---|
| **기준 많이 통과** | ① 둘 다 설명됨 | ② 사업은 통과, 가격에 기대 |
| **기준 적게 통과** | ③ 가격은 낮지만 사업 의문 | ④ 둘 다 확인 필요 |

**①~④ 는 좋고 나쁨의 순서가 아닙니다.** ① 이 항상 좋은 것도 아닙니다 —
시장이 알고 있는 위험을 가격에 반영했을 수 있습니다. 네 칸은 **다음에 무엇을
확인해야 하는가**가 다를 뿐이고, 칸마다 확인 항목이 실제로 다릅니다:

- ② → "가격이 전제한 성장의 근거가 공시에 있는지, 과거 가이던스를 달성해왔는지"
- ③ → "걸린 항목이 업종 구조인지 기업 고유 문제인지 (경쟁사와 비교)"
- ④ → "제 기준이나 모델이 이 기업에 안 맞는 건 아닌지부터"

각 카드의 접힌 부분에 **숫자·한계·확인 항목을 모두 담은 프롬프트**가 있습니다.
복사해 붙이면 공시 기반 정독이 시작됩니다.

## 15. 진단 — 사이드바 버튼

이 대시보드의 상당 부분은 **실제 API 응답을 받아본 적이 없습니다.** 개발 환경에서
DART·SEC·FRED 가 전부 차단되어 있었습니다. 그래서 확인이 필요한데, 전에는
터미널 명령을 안내했습니다. 그건 불친절했습니다.

이제 **사이드바 '진단' 에 버튼 4개**가 있습니다 (탭이 아닙니다 — 매일 보는 화면이 아니라 도구입니다):

| 버튼 | 확인하는 것 | 키 |
|---|---|---|
| 경제지표 계열 확인 | FRED 13개 계열이 실제로 존재하나 | 불필요 |
| 미국 스크리너 확인 | companyfacts 에서 계정이 잡히나 (앞 8개 기업) | 불필요 |
| 재고 지표 확인 | MU 의 XBRL 태그와 DIO 계산 | 불필요 |
| DART 확인 | 재고 구성 계정과 DIO | **필요** |

누르면 실제 응답을 받아 결과를 화면에 띄웁니다. **그 출력을 복사해 Claude 에
붙여넣으면** 틀린 부분을 고칠 수 있습니다. 인증키는 출력에 포함되지 않습니다
(끝 4자리만).

터미널을 선호하시면 같은 것이 명령으로도 됩니다:

```bash
cd stock_dashboard
python -m tools.diagnose --fred      # 경제지표만
python -m tools.diagnose --screen    # 미국 스크리너만
python -m tools.diagnose --xbrl      # 재고 지표만
python -m tools.diagnose --dart      # DART 만 (키 필요)
python -m tools.diagnose             # 전부
```

`python -m tools.diagnose` 는 "tools 폴더의 diagnose.py 를 모듈로 실행" 이라는
뜻이고, `--fred` 같은 것은 그중 일부만 돌리라는 표시입니다. 버튼과 하는 일이
똑같습니다.

## 17. 설계 노트

### 차트가 나이트 모드에서 깨졌던 이유

DIO 막대 그래프만 색상이 하드코딩되어 있었습니다 (`#898781`·`#2a78d6`).
대시보드의 다른 차트는 전부 `var(--dash-*)` 를 쓰는데 이것만 빠져 있어서,
나이트 모드에서 배경과 대비가 안 났습니다. 세 가지를 고쳤습니다:

1. **색상을 CSS 변수로** — 테마를 따라갑니다
2. **밴드 라벨을 왼쪽으로** — 밴드 최대값은 보통 가장 높은 막대와 같아서,
   오른쪽에 쓰면 막대 값 라벨과 **같은 자리에 겹쳤습니다**
3. **가까운 밴드선은 합칩니다** — 최대·중간·최소가 14px 안에 들어오면 하나로
   묶어 "중간·최소 118" 처럼 적습니다. 전에는 선 세 개와 라벨 세 개가 뭉쳐서
   읽을 수 없었습니다

분기 라벨도 두 줄로 나눴습니다 ("2026" / "1분기") — 한 줄이면 옆 라벨과
붙었습니다.

### 실행 없이 잡는 검사 — 튜플 언패킹

개발 환경에 streamlit 이 없어 **app.py 를 실행할 수 없습니다.** 테스트가 전부
통과하는데도 배포하면 죽는 버그가 나올 수 있고, 실제로 하나 나왔습니다:

```python
urgent, soon, _fyi = sig_mod.split_by_urgency(...)   # 2개를 3개로 받음
# → ValueError: not enough values to unpack
```

`split_by_urgency` 는 (긴급, 참고) **두 갈래**인데 요약 화면은 (지금, 이번 주,
참고) **세 갈래**가 필요해서 생긴 실수입니다. 세 갈래용 `split_by_severity` 를
따로 만들어 고쳤습니다 — 두 함수의 용도 차이는 docstring 에 적어 두었습니다.

같은 유형을 막기 위해 `tests/smoke_test.py` 가 **`a, b, c = mod.f()` 의 받는
개수를 피호출 함수의 반환 어노테이션과 대조**합니다. 38개 파일을 훑어
불일치가 있으면 실패합니다. 일부러 틀리게 만들어 **검사가 실제로 잡는 것도
확인**했습니다.

이게 가능한 이유는 반환형에 `tuple[...]` 어노테이션을 붙여왔기 때문입니다 —
어노테이션이 없으면 이 검사가 그 함수를 건너뜁니다.

### '내 종목' 탭의 공시 분석은 **통째로** 접습니다

공시 분석 본문은 종목당 HTML 3개 합쳐 50KB 가 넘습니다. '내 종목' 은 시세와
변화 감지를 보러 오는 화면이니, 분석 섹션 **전체를 하나의 접힘 블록**에
넣었습니다. 접힌 채로도 요약 한 줄은 보입니다:

```
▸ 공시 분석 — MU (1/9종목)
```

어느 종목에 분석이 있고 몇 건이 오래됐는지는 열지 않아도 보이고, 펼치면
실행 버튼과 본문이 나옵니다. 본문 자체도 안에서 한 번 더 접힙니다
(`embed=True`). 출처 목록은 본문을 읽을 때 쓰는 것이라 이 맥락에서는 생략합니다.

**이 수정은 한 번 실패했습니다.** 처음에는 본문만 접었는데, 그래도 위젯이
20개 넘게 남아 화면이 길었습니다. 게다가 그 수정 자체가 `str.replace` 의
패턴 불일치로 **조용히 적용되지 않았습니다** — 못 찾아도 오류가 나지 않기
때문입니다. 그래서 `tests/smoke_test.py` 에 **app.py 소스를 AST 로 검사하는
블록**을 넣었습니다: 내 종목 탭이 분석을 `embed=True` 로 호출하는지,
그 호출이 `with` 블록(접힘) 안에 있는지를 확인합니다. 스트림릿 위젯은 직접
테스트하기 어렵지만, "수정이 실제로 적용됐나" 는 이렇게 잡을 수 있습니다.



**에러 격리.** 한 종목 조회가 실패하면 그 카드만 "데이터 없음"으로 바뀌고 사유를
표시합니다. 소스 하나가 전부 죽어도 나머지 섹션은 정상 렌더링됩니다.
숫자를 추정해서 채우는 경로는 없습니다 — 값이 없으면 `—` 입니다.

**색상.** 등락 색상은 대비·색각이상 분리도 검사를 통과한 조합입니다
(다크: 상승 `#e66767` / 하락 `#3987e5`, 색각이상 ΔE 19.2, 정상시야 ΔE 29.0).
색상만으로 방향을 전달하지 않도록 `▲` / `▼` 기호와 부호를 항상 같이 표시합니다.
사이드바에서 한국 관례(상승 적색)와 미국 관례(상승 녹색)를 바꿀 수 있습니다.

**이스케이프.** 카드를 HTML 문자열로 조립하므로, 외부 API 가 돌려준 모든 문자열은
`html.escape(quote=True)` 를 통과합니다.

## 18. 테스트

```bash
python tests/smoke_test.py      # 계산·포맷·렌더링·설정 정합성
python tests/runner_test.py     # 실행 엔진 (가짜 claude 로 성공·실패·중단 전 경로)
python tests/signals_test.py    # 변화 감지 (신호 발생·미발생 조건, 묶기, EDGAR 파싱)
python tests/cycle_test.py      # 재고 지표 (계정 매칭, DIO 계산·가드, DART 파싱)
python tests/xbrl_test.py       # EDGAR XBRL (중복 제거, 구간 분류, 정렬, 태그 폴백)
python tests/macro_test.py      # 매크로 (CSV 파싱, 전년대비, 임계값 6종, 뉴스 선별)
python tests/buffett_test.py    # 스크리너 (companyfacts 파싱, 기준 6종, 거짓통과 가드)
python tests/dcf_test.py        # 역DCF (왕복 일치, 정규화, 사분면, 한국 기준)
```

`smoke_test` 는 괴리율 계산, 통화 환산, 결측 처리, 숫자 포맷, 실패 카드 렌더링,
HTML 이스케이프, 설정 정합성을 네트워크 없이 검증합니다.

`runner_test` 는 임시 디렉터리에 가짜 `claude` 실행 파일을 만들어 실행 엔진의
전 경로를 통과시킵니다 — 성공, HTML 미생성, 오류 종료, 중단, 좀비 프로세스 감지,
경로 정제, 실패 사유 번역. claude CLI 설치 여부와 무관하게 돌아갑니다.

`macro_test` 는 FRED CSV 의 `.` 결측 처리, 헤더명이 바뀌어도 위치로 읽는지,
전년대비가 **기준연도와 무관**한지(지수 계열의 핵심), 최신값을 제외한 평균,
`0.00` 을 통과하는 부호 전환, 임계값 6종, 뉴스 대상 상한을 검증합니다.

`xbrl_test` 는 네트워크 없이 XBRL 경로를 검증합니다 — 같은 기간 중복 보고에서 제출일
최신 건만 남는지, 53주 분기(97일)와 반기(180일)를 올바르게 분류하는지, 시점값(재고)을
구간값(매출원가) 종료일에 허용치 안에서 붙이는지, 태그 후보를 순서대로 폴백하는지,
그리고 **회계연도 표기가 어긋나도 종료일 순서가 유지되는지**(이 정렬 회귀 테스트를
쓰다가 실제 버그를 찾았습니다).

Streamlit 레이어는 `streamlit run app.py` 로 직접 확인해야 합니다. 설치 없이
레이아웃만 보려면 `python -m tools.preview` 로 `preview.html` 을 만드십시오 —
탭 전환·나이트/데이 전환·3사 재고 패널이 모두 정적 HTML 로 들어갑니다.

## 19. Streamlit Cloud 에 올리기

### 먼저 — zip 을 업로드하는 방식이 아닙니다

Streamlit Community Cloud 는 **GitHub 리포지터리를 연결**해서 배포합니다.
zip 업로드 기능이 없습니다. 그래서 순서가 이렇습니다:

```
zip 압축 풀기  →  GitHub 리포지터리로 올리기  →  Streamlit Cloud 에서 연결
```

### 올리기 전에 반드시 읽을 것 — 안 되는 것들

| 기능 | Streamlit Cloud 에서 | 왜 |
|---|---|---|
| 시세·매크로·공탐지수·VIX | **됩니다** | 공개 API, 키 불필요 |
| 미국 발굴·밸류에이션 (EDGAR) | **됩니다** | 키 불필요, 연락처만 필요 |
| 국내 발굴·재고 지표 (DART) | 됩니다 | Secrets 에 키를 넣어야 합니다 |
| **공시 분석 실행 버튼** | **안 됩니다** | Claude Code CLI 가 없고 로그인도 불가합니다 |
| **저장된 분석 유지** | **안 됩니다** | 컨테이너가 재시작되면 파일이 사라집니다 |

**공시 분석(3종 스킬 실행)은 Streamlit Cloud 에서 쓸 수 없습니다.** 버튼이
'실행 불가' 로 표시됩니다. 그 기능이 필요하면 **내 컴퓨터에서 돌려야** 합니다.
배포는 "밖에서도 시세·매크로·발굴을 본다" 는 용도로만 쓰는 게 맞습니다.

### 가장 중요한 주의 — 앱이 공개됩니다

Streamlit Community Cloud 앱은 **URL 을 아는 사람 누구나 볼 수 있습니다.**
이 대시보드에는 **수빈님 보유·관심 종목이 그대로 들어 있습니다.**

세 가지 선택지가 있습니다:

1. **접근 제한** — 앱 설정에서 열람자를 본인 이메일로 제한합니다
   (무료 플랜의 비공개 앱 개수 제한은 Streamlit 쪽에서 확인하십시오)
2. **종목을 Secrets 로 분리** — `config.py` 의 워치리스트를 코드에서 빼고
   Secrets 에서 읽게 고칩니다
3. **배포하지 않고 내 컴퓨터에서만** — 공시 분석도 되고 노출도 없습니다

**리포지터리를 비공개로 하는 것만으로는 부족합니다.** 리포지터리 공개 여부와
앱 공개 여부는 별개입니다 — 비공개 리포로 배포해도 앱 URL 은 열려 있습니다.

### 1단계 — GitHub 에 올리기

압축을 푼 폴더에서:

```bash
git init
git add .
git commit -m "주식 대시보드"
git branch -M main
git remote add origin https://github.com/<사용자명>/<리포지터리명>.git
git push -u origin main
```

`.gitignore` 가 들어 있어서 **인증키와 생성된 분석은 커밋되지 않습니다**:

| 제외되는 것 | 왜 |
|---|---|
| `.streamlit/secrets.toml` | **인증키** — 절대 커밋 금지 |
| `analysis/*/*.html`, `meta.json` | 생성된 분석 — 공개 리포면 내용이 공개됩니다 |
| `**/.jobs/` | 실행 상태 파일 |
| `preview.html`, `__pycache__/` | 산출물 |

커밋 전에 `git status` 로 `secrets.toml` 이 **목록에 없는지** 확인하십시오.

### 2단계 — Streamlit Cloud 에서 배포

1. [share.streamlit.io](https://share.streamlit.io) 에서 GitHub 로 로그인
2. **New app** → 리포지터리·브랜치 선택, Main file 에 `app.py`
3. **Advanced settings** → **Secrets** 칸에 아래를 붙여넣습니다:

```toml
DART_API_KEY = "40자리_인증키"
EDGAR_USER_AGENT = "stock-dashboard/1.0 (내이메일@example.com)"
```

4. **Deploy** — `requirements.txt` 를 자동으로 설치하고 URL 을 발급합니다

**Secrets 를 반드시 루트 레벨에 두십시오.** Streamlit 은 루트 레벨 시크릿만
환경변수로 노출하고, 이 앱은 환경변수에서 읽습니다. `[섹션]` 안에 넣으면
읽지 못합니다.

### 3단계 — 올린 뒤 확인

앱이 뜨면 **사이드바 → 진단**에서 버튼을 눌러 보십시오. 로컬과 클라우드의
네트워크 환경이 다르므로, 여기서 처음 실패가 드러날 수 있습니다:

- 경제지표 계열 확인 → FRED 가 열리는지
- 미국 스크리너 확인 → SEC 가 `EDGAR_USER_AGENT` 를 받아주는지
- DART 확인 → Secrets 의 키가 전달됐는지

### 내 컴퓨터에서 돌릴 때의 키 설정

배포하지 않고 로컬에서만 쓰실 경우:

```bash
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
# secrets.toml 을 열어 키를 채웁니다 (.gitignore 에 있어 커밋되지 않습니다)
streamlit run app.py
```

환경변수로 직접 넣어도 됩니다:

```bash
# macOS / Linux
export DART_API_KEY="40자리_인증키"
export EDGAR_USER_AGENT="stock-dashboard/1.0 (내이메일@example.com)"

# Windows PowerShell
$env:DART_API_KEY = "40자리_인증키"
$env:EDGAR_USER_AGENT = "stock-dashboard/1.0 (내이메일@example.com)"
```

### 다른 배포처

Streamlit Cloud 의 제약(공시 분석 불가, 파일 비영속)이 걸리면:

- **직접 서버/VPS** — 전부 동작합니다. `claude` CLI 설치와 로그인이 필요합니다
- **Docker** — 같은 조건. `requirements.txt` 와 `streamlit run` 만 있으면 됩니다

어느 쪽이든 **종목 정보가 공개되지 않게** 접근 제어를 먼저 정하십시오.

## 20. 아침 자동 수집 · 장중 갱신 · 인증키 지우기 (2026-11-12)

**아침 자동 수집.** `tools/collect.py` 가 앱과 같은 함수를 같은 인자로 불러
모든 화면의 데이터를 받고 `seed.pkl.gz` 한 파일로 묶습니다. GitHub Actions
(`tools/collect_workflow.yml` → 저장소 맨 위 `.github/workflows/collect.yml`
로 복사)가 매일 06:30 · 평일 15:50 (KST) 에 돌려 `data` 브랜치에 덮어씁니다.
앱은 깨어난 첫 화면에서 그 파일을 읽어(`config.SEED_URL`) 바로 그리고,
'몇 시간 전 값' 이라고 적은 뒤 뒤에서 새로 받습니다.

- 스냅샷은 **공개**됩니다. 공개 데이터만 들어가고 보유 종목(PORTFOLIO)은
  수집하지 않습니다.
- 인증키가 한 글자라도 섞인 항목, 받기에 실패한 항목은 넣지 않습니다
  (앱이 직접 받습니다).
- 스냅샷이 없거나 못 받아도 앱은 예전처럼 직접 받습니다.
- 키는 GitHub 저장소 Settings → Secrets and variables → Actions 에
  `DART_API_KEY`, `FRED_API_KEY` 로 넣습니다.

**장중 갱신.** 차트 조건은 장이 열려 있는 동안 5분마다 다시 계산하고
(`config.CHART_TTL_OPEN_SEC`) 화면에 '장중 잠정 · HH:MM 기준' 이라고 적습니다.
봉이 완성되지 않았으므로 조건은 종가에 달라질 수 있습니다. 시세는 묵은 값을
바로 보여주지 않고 새 값을 3초까지 기다립니다 (`QUOTE_WAIT_FRESH_SEC`).

**인증키 지우기.** DART · FRED 는 키를 요청 주소에 넣고, 연결 실패 문구에는
그 주소가 통째로 들어옵니다. `sources/safe.py` 가 오류가 만들어질 때, 화면에
찍힐 때, 진단 결과를 보여줄 때 세 번 지웁니다.

**기본 부품 색.** `.streamlit/config.toml` 이 적용되지 않으면 스트림릿이 기기의
다크 모드를 따라가 접는 칸 제목 등이 밝은 바탕에 흰 글자로 나옵니다.
`theme.build_native_rules()` 가 기본 부품의 색을 직접 정해 기기 설정과
무관하게 보이게 합니다.
